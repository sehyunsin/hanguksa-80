# 주요 설계 결정과 이유

## 1. 기술 스택
- **React 19 + TypeScript + Vite 8 + Tailwind CSS 4 + Dexie 4(IndexedDB) + vite-plugin-pwa** — 요구사항의 권장 스택을 따름.
- **Zustand는 쓰지 않음**: 학습 기록의 원본이 IndexedDB이고 Dexie `useLiveQuery`로 화면이 자동 갱신되므로, 별도 전역 상태를 두면 같은 데이터가 두 곳에 생겨 어긋날 위험만 커짐. 화면 내부 상태는 React state로 충분.
- **해시 라우팅 + 상대 경로 빌드(`base: './'`)**: 어떤 정적 호스팅(하위 경로 포함)에 올려도 서버 설정 없이 동작.
- **pdf.js는 필요할 때만 불러옴**: 초기 로딩을 가볍게 하고, 서비스 워커가 함께 캐시해 오프라인에서도 기출 PDF를 볼 수 있음.

## 2. 콘텐츠와 학습 기록 분리
- 콘텐츠(단원·개념·사실)는 앱 번들의 TypeScript 데이터, 학습 기록은 IndexedDB. 기록은 **개념 ID로만** 콘텐츠를 참조 → 콘텐츠를 고쳐도 기록이 초기화되지 않음.
- 요구사항 19절의 테이블 대응: `mastery`(mastery+review_schedule), `history`(learning_history), `wrongs`(wrong_answers), `daily`(daily_goals), `exams`(exam_results), `papers`/`paperFiles`(exam_papers), `settings`(user_settings), `confusions`(개념 혼동 쌍). eras·units·lessons·concepts·persons·events·artifacts·sources·concept_relations는 정적 콘텐츠의 필드(`kind`, `era`, `confusers`, `refs`)로 표현. questions·choices는 저장하지 않고 사실에서 그때그때 생성.

## 3. 문제를 “사실(fact)”에서 생성
- 개념마다 주어 없는 사실 문장(예: “노비안검법을 실시하였다”)을 저장하고, 여기서 OX·선다·빈칸·단답·짝 맞추기·비교·순서·기출형 자료 문제 등 13가지 유형을 만든다.
- 이유: (1) 같은 지식을 여러 형태로 반복(요구사항 3·8절), (2) 손으로 만든 문제 수천 개보다 검증해야 할 원본이 적음(사실 단위로 검증), (3) 정답 위치를 고르게 분산하기 쉬움.
- **오답 선택지 안전장치**: 다른 개념의 ‘구별되는’ 사실만 쓰고, 대상 개념과 같은 키의 사실은 제외. 일반적 서술(`~`)은 오답으로 쓰지 않음. 자동 테스트로 전 개념·전 유형 검사.
- **묶음 개념 보호**: 여러 주체를 묶은 개념(예: 보안회와 대한 자강회)은 “자료 → 대상 파악(clue5)” 유형에서 제외. 자료의 주체와 정답의 주체가 달라지는 잘못된 문제를 막기 위함(브라우저 점검 중 발견해 수정).
- **순서 문제**: 정답을 보기 위치가 아니라 각 개념의 연대 값(`sort`)으로 판정 → 보기를 섞어도 오류 없음. 연대 차이가 0.02 미만인 사건끼리는 함께 출제하지 않음.

## 4. 간격 반복: FSRS(ts-fsrs 5.4.2)
- 검증된 오픈소스 FSRS 구현 사용. 6.x는 Node 24 이상을 요구하고 API가 크게 바뀐 직후라 안정적인 5.4.2 선택.
- 설정: 목표 기억 유지율 0.9, 학습·재학습 단계 10분(요구사항의 “10분 후”), 퍼즈 사용, **최대 간격 = 시험 전날까지 남은 일수**(퍼즈로 넘는 경우도 앱에서 다시 제한) → 모든 개념을 시험 전에 다시 보게 됨. 시험 3일 전부터는 A등급 개념을 최근 2일 안에 안 봤으면 복습에 추가(“시험 직전” 복습).
- 요구사항의 1일·3일·7일·14일·30일 간격은 FSRS가 응답에 따라 자동으로 만들고 조정함(고정 간격보다 개인 맞춤).
- 등급: 오답=Again, “확실하지 않아요” 또는 느린 정답=Hard, 정답=Good, 숙련도 4 이상에서 빠르고 확신 있는 기출형 정답=Easy.
- 신규 개념의 레슨(연속 5~7문제)은 블록이 끝날 때 한 번만 FSRS에 반영(같은 시점의 반복 응답으로 기억 강도가 부풀려지는 것 방지). 세션 내 5분 이내 반복 정답도 반영하지 않음.

## 5. 숙련도 5단계(같은 문제 암기 방지)
1 소개됨 → 2 쉬운 확인 통과 → 3 회상·비교 유형 통과(소개 후 9분 이상) → 4 **하루 이상 간격 후** 기출형 통과 → 5 FSRS 안정도 21일 이상 + 간격 후 연속 정답. 오답이면 단계가 내려가고, 확신 오답이면 한 단계 더 내려감. 단계에 따라 출제 유형이 쉬운 것 → 실전형으로 바뀌고, 직전에 통과한 유형은 뒤로 미룸.

## 6. 하루 계획과 재배분
- 79일 표(요구사항 6절)를 실제 기간에 비례해 늘리거나 줄임. 같은 구간을 두 단원이 나누면 개념 수 비례로 배분.
- 오늘 새로 배울 개념 수 = 오늘 분량 + (어제까지 밀린 수 ÷ 2) − (앞선 수), 하루 최대 기본의 2배. 밀린 상태에선 이미 시작했어야 할 단원의 **A등급과 진단상 취약 개념부터** 배움(요구사항 6·12·13절).
- 세션(약 10분)은 버킷별 남은 시간 비율이 가장 큰 쪽에서 한 단위씩 채워 하루 비율(복습 20/신규 25/반복 15/응용 15/보충 5분)을 지킴. 2·3단계는 비율이 응용·보충 쪽으로 이동.
- 학습 시간은 앱 실행 시간이 아니라 **문제·설명 화면이 보이는 동안**만 재고, 한 항목당 최대 2분까지 인정(방치 시간 제외).

## 7. 오답 분석
- 고른 오답이 다른 개념의 사실이면 그 개념과의 “혼동 쌍”을 기록하고, 이후 보충 시간에 두 개념 비교(분류하기) 문제를 냄(예: 영조를 묻는데 정조의 업적을 고르면 영조·정조 비교).
- 원인은 문제 유형·고른 선택지의 개념·확신도·응답 시간·숙련도로 추정하고, 사용자가 한 번 탭으로 고칠 수 있음(선택 사항).
- 틀린 개념은 같은 세션 끝에 **다른 유형으로** 다시 출제(세션당 1회).

## 8. 기출 분석과 학습 우선순위
- 공식 기출 24개 회차를 **자동 분석**(PDF 글자 + Windows 한국어 OCR → 문항 분할 → 개념 키워드 IDF 매칭). 사람이 1,200문항을 전부 태깅하는 대신, 표본 2개 회차를 검수해 정확도를 공개(단원 약 90%, 개념 약 75~85%).
- 점수가 낮은 문항은 태그를 붙이지 않음(추측으로 빈도를 부풀리지 않기 위함).
- 학습 중요도 = 실제 기출 등장 비율 60% + 잠정 중요도 40%. 자동 분석 오차와 앱에 없는 주제를 고려해 빈도만으로 정하지 않음. 밀린 날의 신규 개념 선택, 복습·응용 문제 선택 가중치에 사용.
- 창작 모의고사의 단원별 문항 수 = 실제 기출 단원별 비중.
- 기출 정답·배점(사실 정보)과 분석 결과만 앱에 넣고, 문항 본문·사진은 넣지 않음.

## 9. 실제 기출 문제의 취급
- 공식 사이트에 “ALL RIGHTS RESERVED”, 자료실에 “문항에 사용된 사진 등의 저작권은 원저작자에게 있음”이 표기됨 → **기출 문항을 앱에 넣어 배포하지 않음**. 사용자가 공식 자료실에서 직접 받은 PDF를 기기 안에만 저장해 개인 학습에 사용.
- 공식 정답표 24개 회차를 앱에 내장(사실 정보). 사용자가 답지 PDF를 넣으면 다시 읽어 대조 가능하며, 앱의 정답표 읽기 기능은 실제 공식 정답표 24개를 모두 정확히 읽는 것을 테스트로 확인함. ‘정답 없음’(정정) 문항은 전원 정답 처리.
- 최근 5개 회차(76~80회)를 기본 “실전 평가 전용”으로 지정. 실제 기출 문항은 학습 과정에 섞이지 않으므로(학습 문제는 모두 창작) 평가 전 노출이 없음.
- 실제 기출 성적과 창작 모의고사 성적은 구분해 저장·표시.

## 10. 정직한 표시
- 출제 빈도는 실제 기출에서만 계산(자동 분석 추정치로 표시). A/B/C 잠정 중요도는 보조 값으로만 사용.
- 합격 확률(%)을 표시하지 않음. 대신 요구사항의 최종 준비 기준(처음 보는 실제 기출 5회 평균 75·최저 65·시간 내) 체크리스트를 표시.
- 개념마다 출처 대조 상태(대조 완료 / 일부 확인 / 검증 대기)와 근거 항목 링크를 표시하고, 근거를 못 찾은 사실은 개념 화면에 그대로 보여 줌. 1차 대조는 한국민족문화대백과사전, 백과사전에 없는 교과서식 서술은 우리역사넷(국사편찬위원회 신편 한국사·역대 국사교과서)으로 확인. 출처끼리 다르면(예: 1책 12법 — 백과사전은 부여의 법, 신편 한국사는 고구려도 『구당서』에 12배로 전함) 교과서 서술을 유지하되 메모로 알림.
- 자동 대조는 핵심어와 나머지 내용이 같은 문장 근처에서 함께 맞을 때만 ‘확인’으로 침. 핵심어만 맞은 경우(약한 자동 확인)는 사람이 출처를 읽기 전까지 미확인으로 처리 — 표본에서 핵심어만 맞은 사실 중 엉뚱한 항목(인물 송상현, 모기향, 같은 이름의 다른 지도)과 일치한 예가 나왔기 때문.
- 학설이 나뉘는 서술은 시험 문장으로 쓰지 않음(예: 고이왕 율령 반포 → 뇌물 처벌법으로 바꾸고, 율령 반포가 오답 선택지로도 나오지 않게 같은 비교 키로 묶음). 근거를 못 찾은 수식어는 뺌(예: 조미조약 최혜국 대우 ‘처음으로’).
- 대조 근거는 항목 **본문 서술**만 인정(관련 항목 목록·참고문헌·사진 설명 제외), 한 글자 핵심어와 다른 항목의 단순 동시 출현은 근거로 치지 않음 — 표본 검사에서 잘못된 확인이 나왔기 때문.
- 사료는 원문 인용 대신 요지를 쉬운 말로 풀어 쓰고 그 사실을 화면에 표시. 원문은 공식 데이터베이스(조선왕조실록·한국사데이터베이스·국가법령정보센터)의 해당 기사 **링크만** 연결 — 실록 국역·한국사데이터베이스 번역문은 각 기관의 저작물이라 옮겨 싣지 않음.
- 오답 선택지는 다른 개념의 사실을 쓰므로, 그 사실이 대상에도 맞을 수 있는 조합을 자동으로 찾아 사람이 판단한 목록(`src/content/overlaps.ts`)으로 거름. 애매하면 오답에서 빼는 쪽(문제 수가 조금 줄어도 정답이 둘인 문제를 내지 않음). 새 콘텐츠가 점검에 걸리면 테스트가 실패하게 해 판단을 빠뜨리지 않음.
- 문화유산 사진은 원본 페이지에서 이용 조건을 확인한 것만(퍼블릭 도메인·CC0·CC BY-SA·공공누리 제1유형) 위키미디어 공용에서 받아 크기만 줄여 앱에 넣고, 사진마다 작가·라이선스·원본 링크를 화면에 표시. 사진 문제의 오답 보기는 다른 사진의 문화유산이라 사진을 알아봐야만 풀 수 있게 함(같은 시대 사진을 먼저 오답으로).

## 11. 게임 요소
- XP는 실제로 푼 문제·소개 화면에만(정답 5~12, 오답 1, 세션 완료 20, 하루 목표 50). 하트·오답 제한 없음, 복습은 언제든 가능. 연속 학습일은 하루 10분 이상 학습한 날 기준.
